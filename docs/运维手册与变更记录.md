# dialog-fence 运维手册与变更记录

> 本文档回答四个问题：**怎么用**、**怎么改**、**怎么排查**、**改了什么**。
> 设计原理见同目录 [设计与实施方案.md](设计与实施方案.md)。

- 当前版本：**0.6.0**
- 数据目录：`<DSH_HOME>/dialog-fence/rules/`（`DIALOG_FENCE_DIR` 可覆盖；本机即
  `C:\Users\<你>\AppData\Roaming\dsh-desktop\harness\dialog-fence\rules`）
- 两层规则：`common/`（通用，对每个对话生效）+ `sessions/<id>/`（会话专属，可选）

## 一、日常使用

### 1.0 界面一览

| 界面 | 位置 | 管什么 |
|---|---|---|
| **设置页** | 设置左栏 → 「对话围栏」 | **主入口**：总开关 + **通用规则的直接编辑**（逐条内联改 / 增 / 删 / 清空） |
| **插件详情页配置区** | 左侧「插件」→ **已安装** → dsh-dialog-fence → 详情页（包描述与行之间） | 同一份界面 |
| 会话按钮 | 会话右上角工具区「围栏」+ 条数徽标 | 打开**本会话**专属规则浮层 |
| 规则浮层 | 右下角面板（宽 480px） | 逐条查看 / **单行内联编辑** / 删除 / 新增 / 启停 / 清空 |
| 插件页标签页 | 设置 → 内置插件 → 「对话围栏」 | 同一份界面（老入口） |

五处界面写的是同一份文件：改完 → 落盘 → 下一轮装配时重新读 → 生效。没有状态分叉。

> 0.5.0 起本插件按**组合包**安装，所以卡片在「**已安装**」分组（不再是「官方」分组）；
> 配置区通过 `plugins.bundle.config` 槽位（key = 包名 `dsh-dialog-fence`）渲染在该包详情页里。
>
> 0.6.0 起设置页**不再展示 sessionId 表**（用户 CR-12：「展示 sessionId 没有意义」），
> 改成直接编辑通用规则正文。会话专属规则仍在会话头部那个「围栏」浮层里。

### 1.1 可视化面板（Web / DSH Desktop）

重启后，**设置左栏 → 「对话围栏」** 就是主编辑入口（对每个对话生效的通用规则）：

- 顶部：总开关 pill + 「关闭围栏 / 开启围栏」按钮 + 一句说明 + `规则目录：<DATA_DIR>/common`。
- 每条通用规则占一行：序号 + 正文 + 下方灰字文件名 + 「改」「删」。
- 点「改」把该行就地变成**单行输入框**，`Enter` 保存 / `Esc` 取消 —— **没有 textarea**。
- 底部单行输入框新建一条，旁边「清空全部」；末尾实时显示
  `注入 N 字符 ≈ M token · K/40 条 · 单条上限 2000 字符`。
- 所有改动**下一轮生效**，不需要重启。

会话头部那个 **「围栏」** 按钮管的是**本会话专属**那一层：

- 按钮上的数字 = 当前会话专属规则条数；高亮（`data-on="true"`）= 已启用。
- 浮层底部会提示「通用规则 N 条也会叠加到本对话」。

面板与三处配置页都走宿主注册的 `GET/HEAD/POST /api/dialog-fence` 路由（由 `connection.fetch` 提供，自带 Connection 层鉴权）。通用规则用 `?scope=common` / `{scope:'common'}`，不需要 sessionId。CLI / TUI / headless 没有 `connection` 服务，插件会静默跳过路由注册，`/fence` 命令照常可用。

### 1.2 斜杠命令（所有形态）

在**任意想加围栏的对话**里直接用斜杠命令（命令由插件注册，宿主内建 UI 会提示）：

| 命令 | 作用 |
|---|---|
| `/fence` | 查看本会话围栏状态（启用与否、规则条数、实际注入文本、token 估算） |
| `/fence on` / `/fence off` | 启用 / 停用本会话专属规则（不影响通用规则） |
| `/fence add <规则文本>` | 追加一条**本会话**规则（= 新建一个 txt；自动启用；重复文本不会重复添加） |
| `/fence rm <序号>` | 删除本会话第 N 条 |
| `/fence clear` | 清空本会话规则文件（保留启用状态） |
| `/fence reset` | 彻底删除本会话记录 |
| `/fence dir` | 打印本会话规则目录、通用规则目录与全局 `state.json` 路径 |
| **`/fence all`** | 查看**通用规则**（对每个对话都生效） |
| **`/fence all add <规则文本>`** | 追加一条通用规则 |
| **`/fence all rm <序号>`** | 删除第 N 条通用规则 |
| **`/fence all clear`** | 清空通用规则 |
| `/fence help` | 帮助 |

要点：

- **通用规则对每个对话生效**（包括新开的对话）；**会话规则只作用于当前会话**。两层都为空时渲染空字符串 → 零注入、零 token。
- 规则改动**下一轮立即生效**，不需要重启。
- 单条 ≤ **2000** 字符；每层最多 40 条 / 渲染总 2400 字符封顶。
- 规则里**不要写 `{{ }}`**：宿主的 `interpolate()` 遇到未注册变量会抛错。插件已用 `try/catch` 兜底（降级为空），但内容会静默失效。

### 1.3 直接编辑规则文件（0.3.0 起，每条规则一个 txt）

数据目录默认 `<DSH_HOME>/dialog-fence/rules`（`DIALOG_FENCE_DIR` 可改位置，`/fence dir` 会打印实际路径）。
本机 `DSH_HOME` = `C:\Users\<你>\AppData\Roaming\dsh-desktop\harness`。

> 0.5.0 起这个路径**不再跟着插件包目录走**：宿主半边的 `resolveDshHome()` 从插件所在目录向上找
> 第一个同时含 `profiles/` 与 `sessions/` 的祖先（= DSH home）。这样无论插件是
> `<home>/dialog-fence/`（开发态 `file:///`）还是 `<home>/profiles/.generations/live/<gen>/node_modules/dsh-dialog-fence/`
> （组合包快照），规则都落在同一个 `<home>/dialog-fence/rules`，升级换代不丢。
> 包目录里的 `dialog-fence/rules/` 是 0.4.0 及更早遗留的，可以手工合并过来后删除。

```
rules/
├── state.json                          ← 只存开关，不存正文
├── common/                             ← 通用规则：对每个对话都生效（0.6.0）
│   ├── 01-evidence.txt                 ← 文件名前缀决定注入顺序
│   └── 02-uncertainty.txt
└── sessions/                           ← 会话规则：只对该会话生效
    └── session-<uuid>/
        ├── 01-no-outside-edits.txt
        └── 02-flag-uncertainty.txt
```

注入顺序：先 `common/` 的编号 1..N，再把该会话启用的专属规则接在后面连续编号。

`state.json` 形状：

```json
{
  "version": 2,
  "global": { "enabled": true },
  "sessions": {
    "session-<uuid>": { "enabled": true }
  }
}
```

**规则正文就在 txt 文件里**，文件内容即注入文本（首尾空白会被 trim）。行为规则：

| 你做的事 | 结果 |
|---|---|
| 往 `common/` 里丢一个 `.txt` | 对**所有对话**立即生效（包括新开的） |
| 往 `sessions/<id>/` 里丢一个 `.txt` | 该会话**自动启用**并生效（即使 `state.json` 里没有这个会话） |
| 改 txt 内容 | 下一轮注入的文本跟着变 |
| 删掉 txt | 该条规则消失 |
| 文件为空 / 全空白 | 不算规则，跳过 |
| `state.json` 里显式 `enabled: false` | 保留文件但不注入 |
| `global.enabled: false` | 两层一起静音，文件原封不动 |

⚠ **必须用 UTF-8（无 BOM）写入**。历史事故见「变更记录 · 事故 1」。插件已做编码自动探测（UTF-8 BOM / UTF-16LE 都能读），但仍建议用编辑器或 `node` 写，不要用 PowerShell 的 `Set-Content` / `Out-File` / `>` 重定向。

## 二、怎么改插件代码

1. 编辑 `harness/dialog-fence/index.js`（宿主半边）或 `harness/dialog-fence/client.js`（浏览器半边）。
2. **必须重启 DSH Desktop 才生效**（实测：`dsh-hmr` 未重载本插件，见「变更记录 · 事故 2」）。`client.js` 同样需要重启 —— 浏览器 bundle 由 `dsh-client-modules` 在启动时按 graph 组装。
3. 改完先跑四个无宿主测试（不需要宿主，也**不碰线上 `rules/` 目录**）：

```powershell
$env:ELECTRON_RUN_AS_NODE="1"
$exe = "D:\DSH Desktop\DSH Desktop.exe"
$dir = "C:\Users\<你>\AppData\Roaming\dsh-desktop\harness\dialog-fence"
& $exe "$dir\test\smoke.mjs"
& $exe "$dir\test\route.mjs"
& $exe "$dir\test\client.mjs"
& $exe "$dir\test\render.mjs"
```

期望输出四行：

```
OK all dialog-fence smoke assertions passed
OK all dialog-fence route assertions passed
OK all dialog-fence client bundle assertions passed
OK all dialog-fence render assertions passed
```

四个测试各管一段：

| 测试 | 覆盖 |
|---|---|
| `smoke` | 宿主逻辑：隔离性、命令路径、上限、编码兼容、`ctx.inject(['connection'])`、每条规则落成 txt、**直接操作文件四种情形** |
| `route` | HTTP API：GET（overview / snapshot）、HEAD、POST、按 `file` 寻址的 update/remove、`toggleGlobal`、非法入参 400、405 |
| `client` | 浏览器 bundle 形态：`__ModuleLoader__.load`、`factory`、导出、无裸 `import`、三个 slot 注册签名、**无 `createElement('textarea')`**、`dsh.client` 解析链复算 |
| `render` | 用 DSH 自带的**真 React 18** 把头部按钮与插件页真渲染一遍（`react-dom/server` 的 `renderToStaticMarkup`），确认组件在真 hooks 运行时下不违规、首帧产出预期 DOM |

`render` 只看首帧 —— `renderToStaticMarkup` 不执行 `useEffect`，「点开面板拉数据」仍需浏览器验证（见下方「验证面板是否真的挂上了」）。找不到真 React 时会打印 `SKIP dialog-fence render test` 并 exit 0。

测试通过 `DIALOG_FENCE_DIR` 把插件指向系统临时目录里的一次性沙箱，跑完自动删除，并在结尾断言线上目录一字未动。

### 临时停用 / 卸载

**只关注入（不卸载插件）**：本包详情页配置区里的总开关，或直接改 `rules/state.json` 的 `global.enabled`。

**方式一（推荐，0.5.0 主推形态）：插件页官方卸载**

左侧「插件」→「已安装」→ 点 **dsh-dialog-fence** → 详情页里点「卸载」。
它走 `pluginManager.removeBundle` → Desktop 的 `profileBundlePackageBackend.remove`，
会把 profile `dependencies` / `dsh.profile.bundles` / `pnpm.overrides` 一并清掉。
规则文件（`<DSH_HOME>/dialog-fence/rules/`）**不会**被删，重新装回来即恢复。

**方式二：loader 开关（不卸载，只停进程）**

本包详情页的行列表里每个 loader 行都有启用/禁用开关（`pluginManager.setPluginEnabled`）。
注意这与围栏的业务总开关是两件事：loader 开关会**停掉整个插件**（按钮、命令、路由全消失），业务总开关只停注入。

**方式三（仅 `file:///` 开发形态）：用安装器卸载**

```powershell
node scripts/install.mjs uninstall      # 只删标记块，rules/ 里的规则文件保留
node scripts/install.mjs status         # 查当前状态（会统计会话数与规则数）
```

**方式四（仅 `file:///` 开发形态）：手工编辑补丁层**

在 `harness/profiles/web/cordis.patch.yml` 里找 `- id: dialog-fence` 那个 insert 块：

```yaml
- insert:
    - id: dialog-fence
      name: "file:///C:/Users/%3C你%3E/AppData/Roaming/dsh-desktop/harness/dialog-fence/index.js"
```

- 临时停用：在 `name:` 同级加 `disabled: true`。
- 彻底卸载：删掉整个 `- insert:` 块（含上方注释）。`rules/` 可保留，重新挂回即恢复。

> ⚠️ **组合包形态与 `file:///` 形态互斥**。两者同时存在时会有两条 loader 行，
> 槽位被重复注册。从 `file:///` 切到组合包之前先 `scripts/install.mjs uninstall`。

### 验证面板是否真的挂上了

重启后在浏览器打开 DSH，看五处：

1. **设置左栏 → 「对话围栏」**：应能看到总开关和**通用规则列表**（0.6.0 起这里是主入口）。
   看不到菜单项 → `settings.section` 注册未生效（客户端没重启或 bundle 没更新）。
2. 设置左栏点进去后，通用规则列表是否显示 `rules/common/` 里的 txt。没有 → 走 `GET api/dialog-fence?scope=common` 看看返回什么。
3. 会话右上角是否出现「围栏」按钮。没有 → 客户端 bundle 未被扫到，检查 `package.json` 的 `dsh.client` 与 `exports['./client']`。
4. 左侧「插件」→「已安装」里是否有 **dsh-dialog-fence** 卡片，点进去详情页里是否有围栏配置区。
   没有卡片 → 组合包没装成（查 `plugin_manager list_bundles` 是否有该条目）；
   有卡片但没配置区 → `plugins.bundle.config` 的 `key` 不是 `dsh-dialog-fence`，或注册未生效。
   宿主侧可用 `cordis_inspect_query`（client / Slots / root=`plugins.bundle.config`）核对 occupant 是否含 `{"key":"dsh-dialog-fence","active":true}`。
5. 点开面板后 DevTools Network 里是否有 `api/dialog-fence?sessionId=...`（会话层）或 `api/dialog-fence?scope=common`（通用层）请求且返回 **200**。
   - 返回 **401** → Connection 层鉴权没过（命令行直接 curl 一定是 401，这是正常的）。
   - 返回 **404** → 宿主路由没注册。0.2.x 曾因 `ctx.get('connection')` 拿到 `undefined` 而必然 404，0.3.0 已改为 `ctx.inject(['connection'], cb)`（见设计文档 5.2）。
   - 返回 **400** → 请求体形状不对（通用层必须带 `"scope":"common"`）。

## 三、排查手册

### 症状：围栏文本没出现在下一轮

按顺序查：

1. **全局开关是否被关掉** —— `/fence status` 第一行会显示全局状态；或看 `rules/state.json` 的 `global.enabled`。
2. **通用层有没有规则** —— `rules/common/` 目录里是否有非空 txt（设置页里应能看到它们）。
3. **（查会话层时）会话 id 对不对** —— `/fence dir` 或 `/fence` 会打印当前 `sessionId`，与 `rules/sessions/` 下的目录名逐字比对。
4. **该层是否有非空 txt** —— 目录里没有 txt、或 txt 全空白，就等于没有规则。
5. **该会话是否被显式停用** —— `state.json` 里 `sessions.<id>.enabled` 为 `false` 时保留文件但不注入。
6. **文件编码** —— 用这条命令看首字节（把路径换成实际文件）：

   ```powershell
   $p="C:\Users\<你>\AppData\Roaming\dsh-desktop\harness\dialog-fence\rules\state.json"
   $b=[System.IO.File]::ReadAllBytes($p); "$($b.Length) bytes, first: $($b[0]),$($b[1]),$($b[2])"
   ```

   - `123,10,32` 或 `123,34,118` = `{` 开头 → UTF-8 正常 ✔
   - `255,254,123,0` = UTF-16LE（能读，但建议改回 UTF-8）
   - `239,187,191` = UTF-8 BOM（能读，但建议去掉）
7. **插件是否被加载** —— 重启后 startup 日志里搜 `dialog-fence`；插件本身只 `console.log` 一行 `ready: data=<路径> context=dialog-fence:rules@118`，不写 DSH 日志文件。

> 0.6.0 的两层模型意味着：**设置页里配的规则对所有对话生效**，会话专属那一层只影响当前对话。
> 当某个对话「明明配了却看不到」时，先分清那条规则是在 `common/` 还是在 `sessions/<某个 id>/`。

### 症状：改完 index.js / client.js 没生效

分两种形态：

- **`file:///` 开发形态**：正常现象，**重启 DSH Desktop** 即可（`dsh-hmr` 不重载本插件）。
- **组合包形态**：除了重启，还要**重装**。官方安装器把源码复制进
  `profiles/.generations/live/<gen>/node_modules/dsh-dialog-fence/`，改源码目录不会影响那份副本。
  插件页「已安装」→ 本包 → 卸载 → 再「添加插件」装一次。
  判断装的是哪份：`plugin_manager list_bundles` 里有 `dsh-dialog-fence` 条目 = 组合包形态；
  没有 = `file:///` 形态。

### 症状：面板左下角显示 `HTTP 404`

0.3.0 已修复（根因见设计文档 5.2：`ctx.get('connection')` 在 `apply()` 时刻取到 `undefined`，路由被静默跳过）。
若仍出现：

1. 确认已完整重启 DSH（不是只刷新页面）。
2. 搜日志里有没有 `[dialog-fence] route ready` 这一行 —— 有则路由已注册，404 应是路径写错；没有则 `connection` 服务没就绪或插件被禁用。
3. 确认访问的是 `api/dialog-fence`（document-relative），不是 `/api/dialog-fence`（浏览器里带前导斜杠也行，但别写成绝对 URL）。

### 症状：缓存命中率突然掉

用 `acp_cache` / `/acp-cache` 看归因。判定口诀：

- `divergence ... tail-append` 或 `tail(params/notes)` → 正常，前缀没坏（围栏改动属于这一类）。
- `mid-history` + `no fold/switch/restart attribution` → 先看 `bili.log` 里 `strict-echo: injected blank reasoning_content on N assistant tool-call message(s)`。这是 **billion-context 自己**在改写历史 assistant 消息，与围栏无关（见「变更记录 · 实测 3」）。
- `PROVIDER-SIDE MISS` / `UPSTREAM TTL EXPIRY` → 上游缓存过期或被驱逐，与本插件无关。

### 真要让围栏永不被压缩

编辑 `C:\Users\<你>\.config\billion-context\billion-context.json`：

```json
{ "compress": { "protectedTools": ["durable/*"] } }
```

代价：旧快照永不折叠，上下文单调增长。默认**不建议**。

**③ 界面改动**

`FencePage` 删掉整张 sessionId 表，三张卡片变成：

1. 「对话围栏（dialog-fence）」：总开关 pill + 关/开按钮 + 说明 + `规则目录：<DATA_DIR>/common`。
2. 「通用规则」：`rules.map(RuleRow)`（序号 + 正文 + 文件名 + 改/删，**仍然是单行 `<input>`，没有 textarea**），
   底部新建输入框 + 「清空全部」，末尾 `注入 N 字符 ≈ M token · K/40 条 · 单条上限 2000 字符`。
3. 「接入真实请求的唯一一段文本」：保留 order 118 的缓存说明。

会话头部浮层的底部多一句：「通用规则 N 条也会叠加到本对话（在「设置 → 对话围栏」里改）」。

**④ 用户那 10 条规则已落盘**

写入 `<DSH_HOME>/dialog-fence/rules/common/01-rule.txt` … `10-rule.txt`（10 个文件，UTF-8 无 BOM，
用 node 写以避免事故 1 的 PowerShell 编码坑），依次是：

1. 结论必须给出可复现证据（命令 / 文件:行号 / 实测输出三者至少其一）；给不出就明说「未验证」。
2. 区分「实测 / 推断 / 记忆」；推断须写明承重假设与证伪方式，未证实的归因不得作为改配置或改代码的依据。
3. 改文件前先读该文件；改配置或数据前先备份，并给出精确回滚路径。
4. 只做被要求的改动：不顺手重构、不删无关代码、不擅自新增依赖或扩大改动面。
5. 密钥、令牌、凭据一律不回显、不落盘、不索要；只报存在性、类型与来源位置。
6. 分工：默认自己动手；仅当任务可并行、边界清晰且会产生大量中间输出（宽面扫描 / 多文件清点 / 长日志大仓检索）时才下放子代理；简报必须自包含（目标、已知事实、待答问题、只读/可写边界、交付格式）；其结论必须带 文件:行号 与 命令，否则只能作为线索而不当证据；只读侦察可并行，任何写入必须串行且写者唯一。
7. 读法：源码与日志按定位后的行号窗口读最小必要片段，不整文件整日志灌入；但自己即将修改的文件、支撑自己结论的关键片段、以及自己改动的验证结果，必须留在主会话，不得只靠转述。
8. 如实报告失败与不确定，不粉饰；未完成就直说还差什么、下一步是什么。
9. 实现类改动走 TDD：先写能复现问题的失败测试/探针并留下红灯读数（BEFORE），再做最小改动使其转绿（AFTER），最后才重构；每步给出真实命令与实测输出；无法先写测试的场景须说明理由并给等价验证。
10. 运行中产生的一次性文件（临时脚本/探针、中间导出、调试日志、缓存副本）须在任务收尾时清理，并说明清掉了什么、剩了什么；证据产物、报告、交付物与用户已有文件不在此列，删除前先确认归属。

**⑤ 验证**

- `test/smoke.mjs` 补：只放 `common/` 的 txt → 任意会话都渲染出来；两层并存 → 编号连续且通用在前；
  `global.enabled:false` → 两层一起静音；`/fence all add|rm|clear` 只动 `common/`。
- `test/route.mjs` 补：`GET ?scope=common`、`POST {scope:'common'}`、通用层不需要 sessionId、
  以及「通用层写入不影响会话层目录」。
- `test/client.mjs` / `test/render.mjs`：断言设置页首帧不含 sessionId 表头，
  且含通用规则编辑区（真 React 渲染断言 `class="dialog-fence-page"` + `总开关` + `通用规则`）。
- 四套测试全绿；文件规模 `index.js` 938 行 / 36,251 B、`client.js` 674 行 / 29,376 B。

**⑥ 代价**

通用规则对**每个对话**生效——这正是用户要的语义（一套边界，所有对话都遵守），
但它不再满足 0.1.0 时代「只影响指定会话」的严格隔离。两层并存让用户自己选择粒度：
跨对话的通用底线放 `common/`，一次性的临时约束放会话层。

### 事故 1（已修复）：PowerShell 写坏 rules.json → 围栏静默消失

**经过**：用 `$state | ConvertTo-Json | [System.IO.File]::WriteAllText(...)` 写规则文件，中文被按 GBK/UTF-16 落盘，最终写成 **0 字节**。插件 `JSON.parse` 抛错 → 被最外层 `catch` 吞掉 → 返回空串 → 围栏无声消失，无任何报错（这次 fail-safe 反而得到真实验证）。

**修复**：`loadState()` / `readRuleFile()` 都改为读 Buffer 后自动探测编码（含 `\u0000` 判定 UTF-16LE），并去掉 BOM；解析失败时 `console.warn` 一次（按 mtime+size 去重，不会刷屏）。

**回归**：`test/smoke.mjs` 断言「UTF-8 带 BOM」与「UTF-16LE」的 `state.json` 与规则文件都能正确读。

**隔离修复**：冒烟测试原先直接读写线上规则文件，测试中途崩溃就会弄丢真实规则。现改为 `DIALOG_FENCE_DIR` 指向 `mkdtemp` 的一次性沙箱，结尾断言沙箱已删、线上目录未被写脏。

**教训**：写含中文的 JSON 一律用 node 或编辑器，**不要**用 PowerShell `ConvertTo-Json + WriteAllText`。

### 事故 2（已知限制）：`dsh-hmr` 不重载本插件

**实测证据**：编辑 `index.js` 加入 UTF-16LE 兼容后，把规则文件写成 UTF-16LE —— 若新代码生效，围栏应显示 `HMRTEST` 规则；实际快照里**围栏整段消失**，说明运行的仍是旧代码。触摸文件时间戳后再试一次，结果相同。

**结论**：改插件代码（`index.js` 与 `client.js` 都算）必须重启 DSH Desktop。`cordis.patch.yml` 里那行 `hot reloads via dsh-hmr` 注释对本插件不成立。

### 实测 3：单变量缓存实验（围栏改动不破坏前缀缓存）

在其余条件不变的前提下，追加一条规则后立刻观测下一次真实请求：

```
#484  10:31:23  input=111.5K  cached=108.4K  hit 97.2%  new=2729  comp=0  ttl=337
```

`ttl=337` 是本次唯一可归因于「围栏文本变化」的 re-bill 量，`new=2729` 是正常的新增对话内容。**围栏改动 ≈ 追加 337 token，不产生前缀重写。**

对照：同期两条 `[cache-seam] mid-history` 告警（`#408` message[3]、`#478` message[46]）与围栏文本变化时刻重合，但根因是 billion-context 自己的 strict-echo 改写：

```
02:28:31 strict-echo: injected blank reasoning_content on 3 assistant tool-call message(s)
02:29:38 ... on 5 ...
02:30:34 ... on 6 ...
```

它不断往**历史 assistant 消息**里补空 `reasoning_content`，每补一条就产生一次 mid-history 偏移。围栏注入发生在消息数组**尾部**，不可能是 message[3] / message[46] 的成因。

另外，`bili.log.old` 里在插件存在**之前**就有 9 条同类 cache-seam（跨 2026-09-30 ~ 10-15 的多个历史会话），进一步排除本插件。

**总账**：本会话 484 次请求，命中率 **95.7%**，折叠净收益 +233.99M token。
